# PLAN-2 — Add .gitattributes and normalize line endings (kill the 190-file phantom diff)

## Goal

`git status` currently shows ~190 files as modified when nothing meaningful changed — every
tracked text file reports "LF will be replaced by CRLF the next time Git touches it". This
buries real changes, makes every diff/review/PR noisy, and confuses tooling. Fix it once:

1. Add a `.gitattributes` that makes LF the canonical in-repo line ending for text files.
2. Renormalize the index so the phantom modifications disappear permanently.
3. Stop tracking the generated `tsconfig.tsbuildinfo` (it churns on every typecheck).

## Files to touch

| File | Change |
|---|---|
| `.gitattributes` | **New file** at repo root |
| `.gitignore` | Add `tsconfig.tsbuildinfo` |
| (index) | `git rm --cached tsconfig.tsbuildinfo`, `git add --renormalize .` |

## Implementation order

### Step 0 — Preconditions (do these checks, don't skip)

- Run `git status --short`. Expect a long list of ` M` entries plus real changes in
  `next-env.d.ts` and `tsconfig.tsbuildinfo` only (verify with `git diff --stat` — if other
  files show *content* changes, STOP and tell the user; renormalizing must not swallow real edits).
- Run `git stash list` — must be empty or noted. Do not renormalize with a dirty stash you might pop later.
- New untracked files `PLAN-*.md` and `graphify-out/` may exist. `graphify-out/` should NOT be
  committed — add `graphify-out/` to `.gitignore` in Step 2 as well. The `PLAN-*.md` files are
  fine to leave untracked (do not add them in this change).

### Step 1 — Create `.gitattributes`

```gitattributes
# Canonical line endings: LF in repo, working tree per-file below
* text=auto eol=lf

# Shell scripts must stay LF even when checked out on Windows (bash chokes on CRLF)
*.sh text eol=lf

# Lockfiles / generated
package-lock.json text eol=lf

# Binary — never touch
*.png binary
*.jpg binary
*.jpeg binary
*.ico binary
*.woff binary
*.woff2 binary
*.pdf binary
```

Note `eol=lf` on the catch-all: this checks files out with LF too. That is safe — VS Code,
Node, tsc, next, eslint all handle LF on Windows — and it prevents the CRLF churn from ever
coming back. (SVGs are text/XML; they are covered by `text=auto` — do not mark them binary.)

### Step 2 — Update `.gitignore`

Append (check the existing file first — do not duplicate lines that are already there):
```
tsconfig.tsbuildinfo
graphify-out/
```

### Step 3 — Renormalize

```bash
git rm --cached tsconfig.tsbuildinfo
git add --renormalize .
git status --short
```
Expect: `.gitattributes` and `.gitignore` added, `tsconfig.tsbuildinfo` deleted-from-index,
and a large set of files staged whose only change is line endings (verify one with
`git diff --cached -- app/page.tsx` — should show the whole file swapped, or nothing visible
with `git diff --cached --stat` showing equal +/- counts; spot-check that no content changed:
`git diff --cached --ignore-cr-at-eol --stat` should show ONLY .gitattributes, .gitignore,
and the tsbuildinfo deletion. If anything else appears there, STOP — that's a real edit
riding along.)

### Step 4 — Commit

```bash
git commit -m "chore: normalize line endings via .gitattributes; untrack tsbuildinfo

Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>"
```

### Step 5 — Verify the fix sticks

```bash
git status --short          # must be clean (except untracked PLAN files)
npx tsc --noEmit            # regenerate tsbuildinfo
git status --short          # tsbuildinfo must NOT reappear
npm test                    # 26 tests still pass
npm run build               # build unaffected
```
Also verify the git hook still runs: `bash .claude/hooks/check-gstack.sh; echo $?` → must
print 0 (this is the file most at risk if `eol` handling went wrong).

## Edge cases a weaker model would miss

- **`--ignore-cr-at-eol` is the safety net.** It is the only reliable way to prove the
  renormalize commit contains zero content changes. Use it before committing, not after.
- **`.claude/hooks/*.sh` executed by bash**: if these get CRLF in the working tree, every
  hook invocation fails with `\r: command not found`. The `*.sh text eol=lf` rule plus the
  hook smoke-test in Step 5 covers this.
- **`next-env.d.ts` is regenerated by Next** — after renormalization it may show modified
  again after a `next build`/`next dev`. That is expected once; the LF-canonical attributes
  make subsequent regenerations a no-op. Do NOT gitignore it (Next's tsconfig references it
  and this repo has it tracked; keep behavior).
- **`core.autocrlf`**: do NOT change the user's global `core.autocrlf` setting. `.gitattributes`
  overrides it per-repo, which is the whole point — the fix travels with the repo.
- **Do not run `git add -A`** — it would also stage the untracked `PLAN-*.md` files and
  anything else lying around. Use `git add --renormalize .` (only re-stages tracked files)
  plus explicit adds of `.gitattributes` and `.gitignore`.
- **`Editorial Quant Design System/` has spaces in the path** — always quote paths in any
  manual git command touching it.

## Acceptance criteria

1. `git status --short` after the commit shows nothing except intentionally untracked files.
2. `git diff --ignore-cr-at-eol <commit>^ <commit> --stat` for the renormalize commit lists only
   `.gitattributes`, `.gitignore`, and `tsconfig.tsbuildinfo` (deletion).
3. `npx tsc --noEmit && git status --short` — `tsconfig.tsbuildinfo` does not reappear as tracked.
4. `bash .claude/hooks/check-gstack.sh` exits 0.
5. `npm test` (26+ tests) and `npm run build` both pass.
6. Editing any `.ts` file and saving it in VS Code produces a 1-line diff, not a whole-file diff.
